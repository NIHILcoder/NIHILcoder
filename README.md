I'm **Proxy Nihil**, building desktop software and exploring peer-to-peer systems. My main project is **[Havvn](https://github.com/NIHILcoder/Havvn)**.

A file transfer sounds simple until the peers live behind different routers. Watching together sounds simple until someone seeks. A desktop app sounds simple until closing the window shouldn't actually close the app. Those are the details I'm working through with Havvn.

## What I work with

- **Languages** — TypeScript and JavaScript for Havvn. Python as well.
- **Interface** — React and Zustand, from torrent lists to private room layouts.
- **Desktop** — Electron and Node.js: windows, files, background processes, and the system tray.
- **Networking** — WebTorrent and WebRTC for sharing and rooms; Transmission for native torrent transfers.
- **Media** — FFmpeg, HLS, and Web Audio for streaming and playback.
- **Around it** — Vitest, webpack, electron-builder, and local persistence with electron-store.
- **Learning** — some machine learning experience; still exploring the fundamentals.

## A few things here

**[Havvn](https://github.com/NIHILcoder/Havvn)** — a desktop P2P hub built on BitTorrent. Downloads, streaming while a file is still arriving, browser share links, private rooms, chat, voice, and watching together.

Most of the work lives in one repository. The interface, desktop integration, torrent engines, and peer connections all have to agree on what's happening. The happy path is short. Reconnecting is where things get interesting.

[Source](https://github.com/NIHILcoder/Havvn) · [Releases](https://github.com/NIHILcoder/Havvn/releases) · [Website](https://nihilcoder.github.io/Havvn/)

## What I'm working toward

- Files stay on your machine and move between peers.
- Sharing is straightforward for the person receiving a link.
- The interface makes connection and transfer states understandable.
- Playback, reconnects, and background transfers feel like parts of the same app.
